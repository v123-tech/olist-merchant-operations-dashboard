# 维护与更新

## 日常只改页面

可编辑 `dist/index.html`、`dist/app.js`、`dist/style.css` 和项目介绍页。保持字段 ID、原有筛选口径和回放边界；修改后本地预览并刷新浏览器，检查经营概览、履约队列、规则报告与订单详情。仓库根目录执行 `npm run check` 检查脚本语法，它不替代浏览器操作验收。

用任意静态服务托管 `dist/`。例如：

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory dist
```

打开 `http://127.0.0.1:8765`；停止服务按 Ctrl+C。此服务仅供维护者预览，线上访客不需要运行它。

## 数据不变，只重导出

先保留现有原项目与原始 ZIP，不直接重写它们。假设原项目位于新仓库旁边的 `../../olist_project`，在新仓库根目录执行：

```powershell
python scripts/export_static.py --source ../../olist_project
python scripts/verify_raw_export.py --source ../../olist_project
$env:OLIST_PYTHON = (Get-Command python).Source
node tests/test_static.mjs ../../olist_project
npm run check
```

`export_static.py` 以只读方式连接原 SQLite，并以白名单字段覆盖新仓库的派生文件 `dist/data/`；不写原模拟处置数据库。导出后要保留 `manifest.json` 的行数、字节数和 SHA-256；不要只替换一份数据，订单、商品、配置、元数据、默认汇总和验证报告须属于同一批产物。

`verify_raw_export.py` 直接读取原 ZIP 的 CSV，对照订单、州、晚收货与金额，不调用原 API 作为唯一依据。`test_static.mjs` 用原 Python API 对照浏览器计算；必须提供可用 Python 和完整原项目。它需要 Node.js；网站运行本身不需要 Node.js。

## 从官方数据完整复现

原始数据不随公开仓库分发。维护者先从 [Olist 官方数据页](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)按其访问规则取得版本 2，核对来源、许可和 ZIP 哈希。当前固定源 ZIP 的 SHA-256 为：

```text
967e41e04fc306fe604e2a693f488995a8b41e5047418f8a5c8e4abd6deca784
```

在独立的重建目录放置仓库中的 Python 脚本、SQL、冻结配置和测试。创建 `data/raw/`，将 ZIP 命名为 `brazilian-ecommerce-v2.zip`；将仓库保留的 [source_download_receipt.json](../evidence/source_download_receipt.json) 复制为该目录中的 `download_receipt.json`。此回执记录原项目实际下载的来源与哈希，不含本地路径或凭据。复现前核对自己取得的文件与此固定输入一致；不能靠手写回执绕过哈希核对。

使用 Python 3.12，并安装 `requirements.txt`。依次运行以下命令；它们会覆盖该重建目录的派生数据库和证据，不应指向唯一的原项目副本：

```powershell
python -m pip install -r requirements.txt
python audit_stage1.py
python pipeline.py
python verify_stage2.py
python generate_analysis_report.py
python replay.py
python -m unittest discover -s tests -p "test_demo_api.py" -v
python -m unittest discover -s tests -p "test_replay.py" -v
```

完整重建需要来源回执和原始文件准备齐全；如果缺失，先解决输入，不能把命令执行失败记为通过。之后以该目录为 `--source` 导出静态数据，运行原始 CSV 核对和 API 对照测试。更换数据版本或规则时，应建立新版本配置、重新计算所有结果，并同步 README 与页面文案。

## 模拟记录如何维护

记录仅存在浏览器 `localStorage`，键为 `olist-portfolio:actions:v1`。无远程动作库可备份，也无需维护云数据库。工作台的“重置模拟记录”清除当前网站、当前浏览器的全部演示状态和备注，不会清除历史订单。

不同浏览器配置文件互不影响；同一配置文件的多个标签页共享状态。支持 Web Locks 的浏览器会串行化保存。清除浏览器网站数据、退出无痕会话、更换域名或协议会失去原记录；不要把它用于真实业务任务或跨设备协作。到达 500 个状态、1,000 条历史或 900,000 字符上限时，应重置演示后继续。

## 发布更新

本次使用 Sites 原生发布流程。保留 `.openai/hosting.json` 中已登记的 `project_id`，不要为同一网站反复创建新站点。发布前先完成本地检查；将同一源码状态同步、保存版本并部署，记录源码提交、版本号、部署状态和实际返回的 URL。只把部署成功并完成所需验收的 URL 作为正式入口。

公开 GitHub 副本只提供 `.openai/hosting.example.json`，不包含实际 Site 身份。实际 `.openai/hosting.json` 留在所有者本地与受控 Sites 源码中；不要把它提交到公开仓库。新建或关联站点时，由 Sites 流程生成本地身份配置。公开发布回执同样省略内部项目、版本和部署标识。

发布后检查 HTTPS、新访问者默认状态、三页入口、筛选和下钻、模拟保存后刷新、重置、窄屏与控制台错误。停止本地预览后再打开线上链接，证明它不依赖本机 Python。将新截图、测试范围、日期和未通过项写入交付记录，再更新 README。

若以后迁到 Cloudflare Pages，静态发布目录为 `dist`，无需构建命令；若迁到 GitHub Pages，应发布 `dist` 内容并检查子路径访问。迁移域名会产生新的浏览器存储空间，旧模拟记录不会自动迁移。原 Sites 账号和 GitHub 账号由作者保管，不需要在仓库放入 token、密码或 `.env`。

## 故障与回退

| 现象 | 处理方式 |
|---|---|
| 默认汇总可见，详情或筛选读不到 | 检查主数据 `.json.gz` 是否完整上传、响应成功，浏览器是否支持 `DecompressionStream`；按页面提示重试 |
| 模拟保存失败 | 查看存储禁用、容量限制或损坏提示；确认后重置当前浏览器记录，不要改历史数据 |
| 页面更新后行为与数据不一致 | 确认整批 `dist/data/` 与脚本来自同一版本；回退到上一个已验收版本 |
| 内地网络打开慢 | 在实际面试网络及不同运营商复测。保留 README、截图和可复现源代码作为说明；截图不能冒充在线交互验收 |
| 平台额度或账号导致暂停 | 查看平台真实状态与用量；费用变更须作者确认，不自动升级套餐 |

需要保管的是 GitHub 仓库所有权、Sites 所属账号/工作空间和现有 Site 标识。不要保存或公开临时发布凭据；不需要额外购买服务器来保持本静态作品在线。
